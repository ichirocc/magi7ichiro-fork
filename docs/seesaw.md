## 1. 一行定義と要約

**シーソー**とは、重み（将来は段や許容ライン）を変えたとき、ある違反の族が減る代わりに別の族が増え、必須（HARD）の件数は変わらない現象である。

要約:

1. 観測したシーソーには 3 つの原因がありうる（§4）。**本物の交換**（両方を減らす盤面が存在しない）、**探索の見かけ**（存在するのに探索が届かない）、**揺れ**（差が乱数のばらつきの中）。
2. 原因で直し方が違う。本物なら止める位置を利用者が決める。見かけなら探索を直す。揺れなら測定を増やす。
3. 2026-11-01〜02 の測定で、「見かけ」が実際にあったことが分かっている（§3.2）。
4. 判定の道具の大半は `tools/loop/` に既にある（§5）。足りないのは、重みを腕ごとに変える仕組みと、族の組ごとの前線を求める拡張（§6）。

「シーソー」という語は、2026-11-01 の外部提案が `docs/weightless_objective.md` §3.2 の W2 を「シーソー現象」と呼んだことに由来する（ユーザー指示「シーソーを改良拡張する」）。

## 2. 用語と記法

| 記号・用語 | 定義 |
|---|---|
| 盤面 x | 職員×日のシフトの割り当て（`Array<IntArray>`）。希望固定・手動固定・置けないシフト（`Problem.mayPlace`・`mayPlaceAt`）を守るものだけを考える |
| 族 | 違反の種類。21 族（`MirrorKeys.all`）。必須は 6 族（`MirrorKeys.hard`＝groupViol・covU・c3n・c3w・pref・extWish）、残り 15 族が SOFT |
| 件数ベクトル f(x) | 盤面 x の族ごとの件数。`UnifiedViolationChecker` が出す `ViolationReport.breakdown`（`MirrorCore.kt:48`）を族の順に並べたもの。f_A(x) は族 A の件数 |
| 必須の件数 h(x) | 必須 6 族の件数の和＝`ViolationReport.hard` |
| 優越 x ≺ y | 「どの族でも f(x) ≤ f(y)、かつ少なくとも 1 族で f(x) < f(y)」。重みを使わない比較（多目的最適化のパレート優越） |
| 非劣の盤面 | 集合の中で、ほかのどの盤面にも優越されない盤面。必須の件数が同じ盤面だけで比べる（§7 の I1） |
| 前線 | 必須の件数を固定したとき、存在しうる全盤面のうちの非劣の盤面の件数ベクトルの集合。厳密に求めるには全探索か厳密ソルバーが要る |
| 支持解・非支持解 | 非劣の盤面のうち、ある正の重みの重み付き和を最小にする盤面が支持解。どの重みでも最小にならない盤面が非支持解（Ehrgott・Gandibleux の用語。§10） |
| 腕 | 比較する設定の 1 つ（例: 旧重み、新重み） |
| 対 | 同じデータ・同じ seed で 2 つの腕を走らせた最終盤面の組。差 Δ = f(新) − f(旧) |
| 交換率 r(A→B) | 対の集合で、族 A が減った対について、ΔB の中央値 ÷ (−ΔA) の中央値。「A が 1 件減るあたり B が何件増えたか」 |
| 競合・調和・独立 | 族 A と B の関係。対の集合で、A と B が逆向きに動く対が多ければ**競合**、同じ向きなら**調和**、どちらとも言えなければ**独立**（Purshouse & Fleming 2003 の分類を件数に写したもの。判定の式は §6.1） |
| 支点 | 交換をどこで止めるかの位置。今は重みの比で暗黙に決まっている。将来は件数の許容ライン（`docs/weightless_objective.md` §4.2）で明示する |
| 膝点 | 前線の上で、片方を少し良くすると他方が大きく悪くなる点（Deb & Gupta 2011）。利用者に見せる候補（§6.4） |

## 4. 判定の手順（PROPOSAL。§6 の道具ができたら DEFAULT の測定手順にする）

族の組 (A, B) について、腕 P（A を押す＝A の重みを上げる）と腕 Q（今のまま）の対の集合から判定する。

```
入力: 対の集合 {(x_P^s, x_Q^s)}（データ×seed）、同じ腕を seed だけ変えた反復
1. 揺れの判定:
   各族の揺れ σ_A = 同じ腕・同じデータで seed を変えたときの f_A の標準偏差（データごとに出し、平均する）
   |ΔA の平均| < 2σ_A または |ΔB の平均| < 2σ_B なら「揺れ」。結論を出さず、対を増やす
2. 見かけの判定（安い順に）:
   2a. 集めた盤面: 同じデータの全腕・全 seed の盤面のうち、必須の件数が最小のものだけを集める。
       腕 P の盤面が、集合のどれかに優越されていたら「見かけあり」
   2b. 前線: 必須 ≤ 今の値、f_A ≤ a のもとで f_B を最小化する（a を起点の f_A から 1 件ずつ下げる）。
       観測した盤面の f_B が、同じ a での最小より大きければ「見かけあり」。差を「見かけの量」と呼ぶ
3. 上のどれにも当たらなければ「本物の交換」
```

- 2a は「見かけがある」ことしか示せない（無いことは示せない）。2b は厳密に解けたときだけ「無い」と言える。CP-SAT が時間切れで可能解しか出さないときは、2b も「ある」側の判定にしか使わない。
- §3.2 の実例は 2b の形（c1 を固定して他を最小化した盤面が、重みで起点を上回った）。

## 6. 提案（PROPOSAL）

### 6.1 S1: 交換の表とシーソーの地図（出力不変）

- **地図**: 族 A ごとに、A の重みだけを ×2 にした腕 P_A を作り、今の重みの腕 Q と対にする。各族 B について ΔB の平均・区間・増/減/同を出す。行＝押した族 A、列＝出てきた族 B の表。
- **競合・調和・独立の判定**（Purshouse & Fleming の分類を件数の対に写したもの。閾値は MAGI 側の案）:
  - 対のうち ΔA < 0 のものだけを見て、ΔB > 0 の割合 p₊ と ΔB < 0 の割合 p₋ を出す。
  - p₊ ≥ 0.6 かつ ΔB の区間が 0 を含まない（正）→ **競合**。p₋ ≥ 0.6 かつ区間が負 → **調和**。どちらでもない → **独立**。
- **連鎖**: 地図を、族を節、競合の辺を矢印（重みは交換率）にした有向グラフにする。A→B→C の経路があれば、A のラインを動かすと C まで波及しうる。
- **実装の罠**（重要）: 重みは定数で、`MirrorKeys.weights`・`Evaluator.fullEvalParts`・`DeltaEvaluator`・C++ `magi_native.cpp` に書かれている（`.claude/rules/weights.md`）。
  腕ごとに重みを変えるには、①腕ごとにビルドする（今の `WeightSwapProbe` の使い方＝旧重みと新重みの 2 ビルド）か、②測定専用の重みの差し替え口を作るかのどちらか。
  ②は C++ の評価器と番兵（native-parity）にも通す必要があり、HF77 の対象外（製品の重みは変えない）であることをコードで保証する（テスト専用の入口にする）。
- 腕の数: SOFT 15 族×1（×2 のみ）で 15 腕。最初は実機ログで目立つ 6 族（c1・high・c3m・c3mn・fair・apt）に絞る案（Q-S2）。
- 揺れ: 腕 Q を seed 6 個で回して σ を出す（§4 の 1）。

### 6.2 S2: 見かけの判定（出力不変）

- **S2a（集めた盤面）**: S1 の全腕・全 seed の最終盤面を、データごとに 1 つの集合にする。必須の件数が最小の盤面だけで非劣の盤面を求め、腕ごとに「優越された盤面の割合」を出す。計算は件数ベクトルの比較だけで、PC で数秒。
- **S2b（前線）**: `c1_floor_cpsat.py` を一般化し、任意の族の組 (A, B) について「必須 ≤ h₀、f_A ≤ a のもとで f_B を最小化」を解く。a を起点の値から 1 件ずつ下げ、(a, min f_B) の列＝前線の断面を出す。
  - ε 制約法（Haimes ら 1971。弱効率解を避ける改良が Mavrotas 2009 の AUGMECON）。MAGI では §7 の I3 のとおり、得た盤面を辞書式で整えればよい（f_B が同じなら他の族の和を最小にする 2 回目の解き直し）。
  - 族を CP-SAT に写すときは、族ごとに `UnifiedViolationChecker` と件数が一致することを起点の盤面で確かめる（`membrane_cpsat.py` と同じ手順）。
- 出すもの: 族の組ごとの判定（揺れ・見かけ・本物）と見かけの量。

### 6.3 S3: シーソーを割る探索（見かけのとき）

- 両端の盤面（P の盤面と Q の盤面）のあいだを Path Relinking（Glover・Laguna・Martí 2000）で歩き、**両端のどちらかに優越する盤面**も拾う。今の `elitePathRelink` は `betterReport` で良い盤面しか拾わないので、拾う条件を足す。
- 拾った盤面は、採否の比較（`betterReport`）に通す。通れば採る。通らなくても、§6.4 の案として残せる（採否は変えない）。
- 作る条件: S2 で見かけの量が 6 fixture 中 2 件以上で 1 件以上あること。作ったら決定的後処理の 2 腕比較で、勝ち＞負け・必須の悪化 0・後処理の時間の増加 5 秒以内（CLAUDE.md の判断の基準、`docs/stall_escape.md` §13 の 4）。
- 既に効いているもの: `MembraneCellLns` は、§3.2 の「シーソーでない改善」を探索の中で拾う役を、細胞の焼きなましで担っている。S3 はその前段（2 端点のあいだ）を足す提案。

### 6.4 S4: 本物の交換の見せ方と支点

- 本物と判定した族の組は、前線の断面（S2b の (a, min f_B)）から 2〜3 点を選んで見せる: **両端**と**膝点**。
  - 膝点は、断面で隣どうしの交換率（Δf_B / Δa）が最も大きく変わる点（Deb & Gupta 2011 の考え方を整数の断面に写したもの。MAGI 側の案）。
- 文言は件数で書く（例:「上限超過を 1 件減らすと、期間の制約が約 2 件増えます」）。重みや点数は出さない。
- 支点の置き方は `docs/weightless_objective.md`: 段が違えば上の段が勝つ（§4.3）、同じ段なら段の中の比べ方（§4.2・§4.2c）、件数で止めたいなら受容度の帯（§4.2b）。
- 案の保持（同 §6.1）の「段の極端案」「妥協案」に、膝点を使う。

### 6.5 S5: 地図を段の割り当ての材料にする

- 強く競合する族を別の段に置くと、上の段が常に勝ち、下の段の族は改善されない。実機ログでは fair・apt を良くする手 421 件が c1 の悪化で落ちた（`docs/weightless_objective.md` §3.4.1）。
- S1 の地図で競合の強い組を示し、段の割り当て（同 Q1）と fair・apt を c1 より先に直すか（同 Q16）の判断材料にする。決めるのは利用者。

## 7. 不変条件

| # | 条件 | 理由 |
|---|---|---|
| I1 | 優越・前線は、必須の件数が同じ盤面どうしでだけ比べる。必須を緩めた前線は出さない | 必須はどの設計でも最上段で緩めない（`docs/weightless_objective.md` §2） |
| I2 | 盤面への書き込み（採用）は `betterReport` だけで決める。S3 の優越は「拾う」条件で、採る条件ではない | 採否の比較は単一ソース（`reportComparator`、CLAUDE.md） |
| I3 | ε 制約で得た盤面は、目的の族が同じ値なら残りの族で辞書式に整える | 弱効率解（ほかの族を下げられる余地を残した解）を案に出さない（AUGMECON の目的と同じ） |
| I4 | S1・S2 は出力不変（`tools/` だけ。製品コードを変えない） | 測定と改修を分ける |
| I5 | 製品の重みは変えない。測定用の重みの差し替えは、製品の経路から呼べない入口にする | HF77 |
| I6 | 交換率・判定には必ず区間と増/減/同の数を添える | 平均の比だけでは揺れと区別できない（§3.1） |

## 8. 採否の規則と統計

- 対の単位は (データ, seed)。差は新−旧。区間は 95% ブートストラップ（`weight_swap_stats.py` と同じ: 4000 回の再標本、乱数 seed 7）。
- 揺れ σ は同じ腕を seed 6 個で回して出す（§4 の 1）。
- S3 の採否は既存の規則（決定的後処理の 2 腕比較、事前基準を先に固定、`docs/stall_escape.md` §13 の 4）。

8. S3 を作る前に、作る条件（§6.3）を満たしているか確かめる。
