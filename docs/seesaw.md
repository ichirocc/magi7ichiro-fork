## 1. 一行定義と要約

**シーソー**とは、重み（将来は段や許容ライン）を変えたとき、ある違反の族が減る代わりに別の族が増え、必須（HARD）の件数は変わらない現象である。

要約:

1. 観測したシーソーには 3 つの原因がありうる（§4）。**本物の交換**（両方を減らす盤面が存在しない）、**探索の見かけ**（存在するのに探索が届かない）、**揺れ**（差が乱数のばらつきの中）。
2. 原因で直し方が違う。本物なら止める位置を利用者が決める。見かけなら探索を直す。揺れなら測定を増やす。
3. 2026-11-01〜02 の測定で、頭打ち盤面が**今の重みでも最適でない**こと（§2 の「見かけ（重み）」）は分かっている（§3.2）。より強い「見かけ（優越）」＝すべての族で負けない盤面があるかは、まだ確かめていない。
4. 判定の道具の大半は `tools/loop/` に既にある（§5）。足りないのは、重みを腕ごとに変える仕組み、最終盤面の書き出し、盤面ごとのパレート判定と前線の断面を求める拡張（§6）。

「シーソー」という語は、2026-11-01 の外部提案が `docs/weightless_objective.md` §3.2 の W2 を「シーソー現象」と呼んだことに由来する（ユーザー指示「シーソーを改良拡張する」）。

## 2. 用語と記法

| 記号・用語 | 定義 |
|---|---|
| 盤面 x | 職員×日のシフトの割り当て（`Array<IntArray>`）。希望固定・手動固定・置けないシフト（`Problem.mayPlace`・`mayPlaceAt`）を守るものだけを考える |
| 族 | 違反の種類。21 族（`MirrorKeys.all`）。必須は 6 族（`MirrorKeys.hard`＝groupViol・covU・c3n・c3w・pref・extWish）、残り 15 族が SOFT |
| 件数ベクトル f(x) | 盤面 x の族ごとの件数。`UnifiedViolationChecker` が出す `ViolationReport.breakdown`（`MirrorCore.kt:48`）を族の順に並べたもの。f_A(x) は族 A の件数 |
| 必須の件数 h(x) | 必須 6 族の件数の和＝`ViolationReport.hard` |
| 優越 x ≺ y | 「どの族でも f(x) ≤ f(y)、かつ少なくとも 1 族で f(x) < f(y)」。重みを使わない比較（多目的最適化のパレート優越） |
| 非劣の盤面 | 集合の中で、ほかのどの盤面にも優越されない盤面。必須の件数が同じ盤面だけで比べる（§7 の I1） |
| 前線 | 必須の件数を固定したとき、存在しうる全盤面のうちの非劣の盤面の件数ベクトルの集合。厳密に求めるには全探索か厳密ソルバーが要る |
| 支持解・非支持解 | 非劣の盤面のうち、ある正の重みの重み付き和を最小にする盤面が支持解。どの重みでも最小にならない盤面が非支持解（Ehrgott・Gandibleux の用語。§12） |
| 見かけ（優越） | 観測した盤面 x に優越する盤面 y が存在する（必須の件数が x 以下で、21 族すべてで f(y) ≤ f(x)、どれかで <）。x はパレートの前線の上に無い＝どんな正の重みでも y に負ける。**シーソーの判定（§4）はこちらを使う** |
| 見かけ（重み） | その腕の重みで、x より重み付きの点数が低い盤面が存在する（探索がその腕の最適に届いていない）。y が別の族を増やしていてもよい。見かけ（優越）より弱い。§3.2 の実例はこちら |
| 腕 | 比較する設定の 1 つ（例: 旧重み、新重み） |
| 対 | 同じデータ・同じ seed で 2 つの腕を走らせた最終盤面の組。差 Δ = f(新) − f(旧)。**同じ seed でも盤面は再現しない**（並列ワーカー・壁時計の予算・後処理の時刻由来の種、`tools/loop/README.md`）ので、対は「条件をそろえた 2 標本」であって、同じ探索の 2 回ではない |
| fixture | `app/src/test/resources/` の 6 件の盤面: `blocked_covu_state`・`full_coverage_state`・`golden_state`・`oct2026_grid_state`・`sample_state_v6`・`sept2026_state`（`.json`）。「6 fixture」はこの全部。`WeightSwapProbe` の既定は blocked_covu と full_coverage を除く 4 件（§5） |
| 交換率 r(A→B) | 対の集合で、族 A が減った対について、ΔB の中央値 ÷ (−ΔA) の中央値。「A が 1 件減るあたり B が何件増えたか」 |
| 競合・調和・独立 | 族 A を押したときの A と B の動き。ΔA の平均の区間が負で ΔB の平均の区間が正なら**競合**、ΔB の区間も負なら**調和**、ΔB の区間が 0 を含めば**独立**（分類の考え方は Purshouse & Fleming 2003。判定は §6.1） |
| 競合率 c(A, B) | 対のうち、A と B の少なくとも一方が動いた対を分母、A と B が逆向きに動いた対を分子にした割合。**記述にだけ使い、判定には使わない**（対は同じ探索の 2 回ではないので、対ごとの向きの一致は重みの効果を表さない。§13.2） |
| 代表点 | 前線の断面から利用者に見せるために選ぶ少数の点。両端・膝点・交換率が大きく変わる点（§6.4） |
| 支点 | 交換をどこで止めるかの位置。今は重みの比で暗黙に決まっている。将来は件数の許容ライン（`docs/weightless_objective.md` §4.2）で明示する |
| 膝点 | 前線の上で、片方を少し良くすると他方が大きく悪くなる点（Deb & Gupta 2011）。利用者に見せる候補（§6.4） |

## 4. 判定の手順（PROPOSAL。§6 の道具ができたら DEFAULT の測定手順にする）

族の組 (A, B) について、腕 P（A を押す＝A の重みを上げる）と腕 Q（今のまま）の対の集合から判定する。

```
入力: 対の集合 {(x_P^s, x_Q^s)}（データ×seed）。盤面そのもの（2b で使う）
1. 揺れの判定:
   ΔA・ΔB それぞれの平均の 95% ブートストラップ区間（§8）が 0 を含むなら「揺れ」。結論を出さず、対を増やす
   （対が 8 未満なら判定しない。σ＝同じ腕・同じデータで seed を変えたときの標準偏差は、必要な対の数の見積もりにだけ使う）
2. 見かけ（優越）の判定（安い順に）:
   2a. 集めた盤面: 同じデータの全腕・全 seed の盤面のうち、必須の件数が最小のものだけを集める。
       腕 P の盤面が、集合のどれかに 21 族の件数ベクトルで優越されていたら「見かけあり」
   2b. 盤面ごとのパレート判定（厳密、PC のみ）: 腕 P の盤面 x ごとに
         最小化 Σ_f f(y)   条件: h(y) ≤ h(x)、すべての族 f で f(y) ≤ f(x)
       を解く。最適値が Σ_f f(x) より小さければ x は優越される＝「見かけあり」。差を「見かけの量」と呼ぶ。
       最適の証明つきで差が 0 なら、x は前線の上にある
3. 2a・2b で見かけが無く、2b が最適の証明つきなら「本物の交換」。2b が時間切れ（可能解のみ）なら「未決」
```

- 2a は「見かけがある」ことしか示せない（無いことは示せない）。2b は厳密に解けたときだけ「無い」と言える。
- 「A と B の 2 族だけで両方減っている盤面」は見かけの証拠にしない。ほかの族 C を増やしていれば、交換が C へ移っただけ（§6.1 の連鎖）。
- 2b の条件は**すべての族**を x の値以下に縛る。A だけを縛って B を最小にする（ε 制約の 1 本）と、ほかの族が増えた盤面が出て、優越の判定にならない。§3.2 の c1 最小の盤面（apt +21・fair +26）がその例で、見かけ（重み）の証拠にはなるが、見かけ（優越）の証拠にはならない。
- 2b には盤面そのものが要る。`WeightSwapProbe` は `MAGI_WS_BOARDS=<ディレクトリ>` で最終盤面も書く（2026-11-04 に追加）。判定の道具は `tools/loop/seesaw_s2b.py`（§13.4）。

## 6. 提案（PROPOSAL）

### 6.1 S1: 交換の表とシーソーの地図（出力不変）

- **地図**: 族 A ごとに、A の重みだけを ×2 にした腕 P_A を作り、今の重みの腕 Q と対にする。各族 B について ΔB の平均・区間・増/減/同を出す。行＝押した族 A、列＝出てきた族 B の表。
- **競合・調和・独立の判定**（2026-11-03 のドッグフーディングで改めた。§13.2）:
  - まず押した族 A が動いたかを見る: ΔA の平均の 95% 区間が負（0 を含まない）でなければ、その腕は「A を押せていない」＝地図の行を出さない。
  - 族 B ごとに ΔB の平均の 95% 区間を出す。正なら**競合**、負なら**調和**、0 を含めば**独立**（未決を含む）。
  - 対が 8 未満なら判定しない（`docs/stall_escape.md` §1 の採否の規則「対 8 以上・95% 区間」と同じ下限。「対」は (fixture, seed) の組で、1 枚の盤面の違反の件数ではない）。
  - 競合率（§2）と相関係数は記述に添えるだけ。対ごとの向きの一致で判定しない（§11 の R1 の見直し）。
- **連鎖**: 地図を、族を節、競合の辺を矢印（重みは交換率）にした有向グラフにする。A→B→C の経路があれば、A のラインを動かすと C まで波及しうる。
- **実装の罠**（重要）: 重みは定数で、`MirrorKeys.weights`・`Evaluator.fullEvalParts`・`DeltaEvaluator`・C++ `magi_native.cpp` に書かれている（`.claude/rules/weights.md`）。
  腕ごとに重みを変えるには、①腕ごとにビルドする（今の `WeightSwapProbe` の使い方＝旧重みと新重みの 2 ビルド）か、②測定専用の重みの差し替え口を作るかのどちらか。
  ①のホスト JVM の腕では C++ を使わないので、Kotlin の 3 か所（`MirrorKeys.weights`・`Evaluator.fullEvalParts` のリテラル・`DeltaEvaluator` の集約）を直せば足りる。high の例: `MirrorCore.kt` の `"high" to 50.0`、`Evaluator.kt` の `rawHigh * 50L`、`DeltaEvaluator.kt` の `(n - hi).toLong() * 50L`。ほかは `MirrorKeys.weightOf` か `PenaltyWeights` を読むので自動で追従する（§13 で実施）。
  ①の 2 つのビルドは**同時か交互に**走らせる。別々の時間に走らせた CSV を突き合わせない（`tools/loop/README.md`。負荷で結果が変わる）。
  ②は C++ の評価器と番兵（native-parity）にも通す必要があり、HF77 の対象外（製品の重みは変えない）であることをコードで保証する（テスト専用の入口にする）。
- 腕の数: SOFT 15 族×1（×2 のみ）で 15 腕。最初は実機ログで目立つ 6 族（c1・high・c3m・c3mn・fair・apt）に絞る案（Q-S2）。
- fixture は 6 件すべて（`MAGI_WS_FIXTURES` で指定する。既定の 4 件のままにしない）。
- 揺れ: 腕 Q を seed 6 個で回して σ を出す（必要な対の数の見積もり用。§4 の 1）。
- **盤面も書き出す**: §4 の 2b には盤面そのものが要る。`WeightSwapProbe` に、最終盤面を (fixture, seed, arm) ごとの JSON で書く出力を足す（`tools/loop/OptDump.kt` が盤面の書き出しの前例）。

### 6.2 S2: 見かけの判定（出力不変）

- **S2a（集めた盤面）**: S1 の全腕・全 seed の最終盤面を、データごとに 1 つの集合にする。必須の件数が最小の盤面だけで非劣の盤面を求め、腕ごとに「優越された盤面の割合」を出す。計算は件数ベクトルの比較だけで、PC で数秒。
- **S2b（盤面ごとのパレート判定）**: §4 の 2b。腕 P の盤面ごとに「必須 ≤ h(x)、全族 ≤ f(x) のもとで Σ_f f を最小化」を解く。差が出れば見かけ（優越）の量。族は `membrane_cpsat.py` の写し（fair は表で写す版）を使う。
- **S2c（前線の断面、S4 用）**: `c1_floor_cpsat.py` を一般化し、族の組 (A, B) について「必須 ≤ h₀、f_A ≤ a、A・B 以外の族は起点の盤面の値以下 のもとで f_B を最小化」を解く。a を起点の値から 1 件ずつ下げ、(a, min f_B) の列＝起点を通る前線の断面を出す（A・B 以外を縛らないと、ほかの族が増えた盤面が混ざって断面にならない）。
  - ε 制約法（Haimes ら 1971。弱効率解を避ける改良が Mavrotas 2009 の AUGMECON）。MAGI では §7 の I3 のとおり、得た盤面を辞書式で整えればよい（f_B が同じなら他の族の和を最小にする 2 回目の解き直し）。
  - **解く回数の削り方**（AUGMECON2 の bypass と AUGMECON-R の刈り込み、§11 の R2）: a で解いた盤面の f_A が a より小さければ、a から f_A までの断面は同じ盤面なので解かずに飛ばす。
    また、ある a で「条件を満たす盤面が無い」と**証明**されたら（状態 `INFEASIBLE`）、それより小さい a も無いので、そこで打ち切る。時間切れ（`UNKNOWN`）では打ち切らない。
  - **全部の断面は要らない**: 見せるのは代表点（§6.4）だけなので、両端を先に解き、あいだは交換率が大きく変わるところだけを二分で細かくする（前線の代表を選ぶ ε 制約法の考え方、§11 の R2）。
  - 族を CP-SAT に写すときは、族ごとに `UnifiedViolationChecker` と件数が一致することを起点の盤面で確かめる（`membrane_cpsat.py` と同じ手順）。
- 出すもの: 族の組ごとの判定（揺れ・見かけ・本物）と見かけの量。

### 6.3 S3: シーソーを割る探索（見かけのとき）

- 両端の盤面（P の盤面と Q の盤面）のあいだを Path Relinking（Glover・Laguna・Martí 2000）で歩き、**両端のどちらかに優越する盤面**も拾う。今の `elitePathRelink` は `betterReport` で良い盤面しか拾わないので、拾う条件を足す。
- 歩き方は 2 通りを持つ（§11 の R3。反応型 Path Relinking＝内側と外側の組み合わせ）:
  - **内側**: P から Q へ、Q と違うセルを 1 つずつ Q に合わせる（今の `elitePathRelink` と同じ向き）。
  - **外側**: P から、Q と**同じ**セルを 1 つずつ Q と違う値へ変える（Q から遠ざかる）。両端のどちらにも無い組み合わせを探す。
  - どちらを多く使うかは、直近に優越する盤面を拾えた方を増やす（反応型）。
- 族の組が複数あるときは、組ごとに 1 本ずつ歩く（分解型の多目的 Path Relinking、§11 の R3）。
- 拾った盤面は、採否の比較（`betterReport`）に通す。通れば採る。通らなくても、§6.4 の案として残せる（採否は変えない）。
- 作る条件: S2 で見かけの量が 6 fixture 中 2 件以上で 1 件以上あること。作ったら決定的後処理の 2 腕比較で、勝ち＞負け・必須の悪化 0・後処理の時間の増加 5 秒以内（CLAUDE.md の判断の基準、`docs/stall_escape.md` §13 の 4）。
- **置き場所**: 今の `elitePathRelink` はポートフォリオ探索（予算 211 秒以上）でしか走らない（§5）。既定の 60 秒で効かせるなら、S3 は後処理の最終段（`MembraneCellLns` の前後）に置く。両端の盤面は、後処理の中の候補（例: 共同 LNS や膜の細胞の途中の最良）から取る。
- 既に効いているもの: `MembraneCellLns` は、§3.2 の「見かけ（重み）」を探索の中で詰める役を、細胞の焼きなましで担っている。S3 はそれとは別に、2 端点のあいだを歩く提案。

### 6.4 S4: 本物の交換の見せ方と支点

- 本物と判定した族の組は、前線の断面（S2c の (a, min f_B)）から 2〜3 点を選んで見せる: **両端**と**膝点**。
  - 膝点は、断面で隣どうしの交換率（Δf_B / Δa）が最も大きく変わる点（Deb & Gupta 2011 の考え方を整数の断面に写したもの。MAGI 側の案）。
  - 膝点の定義は文献で一致していない（Yu ら 2022 の survey、§11 の R4）。この文書は上の 1 つに固定し、ほかの定義（角度・最遠点など）は使わない。断面が短く（点が 3 つ未満）膝が決まらないときは両端だけを見せる。
- **説明の文**（§11 の R5）: 交換を、利用者が良くしたい族を起点に書く。「期間の制約を 2 件減らすなら、上限超過を 1 件譲ることになります」。どの族を譲るかは S1 の地図の競合の相手から選ぶ（説明可能な対話型多目的最適化の、「良くしたい目的を改善するために悪化を受け入れられる別の目的を示す」型）。
- 文言は件数で書く（例:「上限超過を 1 件減らすと、期間の制約が約 2 件増えます」）。重みや点数は出さない。
- 支点の置き方は `docs/weightless_objective.md` に従う（以下の節番号はその文書のもの）: 段が違えば上の段が勝つ（同 §4.3）、同じ段なら段の中の比べ方（同 §4.2・§4.2c）、件数で止めたいなら受容度の帯（同 §4.2b）。
- 案の保持（同 §6.1）の「段の極端案」「妥協案」に、膝点を使う。

### 6.5 S5: 地図を段の割り当ての材料にする

- 強く競合する族を別の段に置くと、上の段が常に勝ち、下の段の族は改善されない。実機ログでは fair・apt を良くする手 421 件が重み付きの点数の悪化で落ち、そのうち 271 件は c1 の悪化が主因だった（fair 184・apt 87。`docs/weightless_objective.md` §3.4.1）。
- S1 の地図で競合の強い組を示し、段の割り当て（同 Q1）と fair・apt を c1 より先に直すか（同 Q16）の判断材料にする。決めるのは利用者。

## 7. 不変条件

| # | 条件 | 理由 |
|---|---|---|
| I1 | 優越・前線は、必須の件数が同じ盤面どうしでだけ比べる。必須を緩めた前線は出さない | 必須はどの設計でも最上段で緩めない（`docs/weightless_objective.md` §2） |
| I2 | 盤面への書き込み（採用）は `betterReport` だけで決める。S3 の優越は「拾う」条件で、採る条件ではない | 採否の比較は単一ソース（`reportComparator`、CLAUDE.md） |
| I3 | ε 制約で得た盤面は、目的の族が同じ値なら残りの族で辞書式に整える | 弱効率解（ほかの族を下げられる余地を残した解）を案に出さない（AUGMECON の目的と同じ） |
| I4 | S1・S2 は出力不変（`tools/` だけ。製品コードを変えない） | 測定と改修を分ける |
| I5 | 製品の重みは変えない。測定用の重みの差し替えは、製品の経路から呼べない入口にする | HF77 |
| I6 | 交換率・判定には必ず区間と増/減/同の数を添える | 平均の比だけでは揺れと区別できない（§3.1） |
| I7 | 見かけ（重み）だけを根拠に「本物の交換ではない」と言わない。本物か見かけかの判定は見かけ（優越）で行う | 重みで良い盤面は、別の族を増やした交換かもしれない（§3.2） |

## 8. 採否の規則と統計

- 対の単位は (データ, seed)。差は新−旧。区間は 95% ブートストラップ（`weight_swap_stats.py` と同じ: 4000 回の再標本、乱数 seed 7）。
- 揺れの判定は区間だけで行う（§4 の 1）。σ（同じ腕を seed 6 個で回した標準偏差）は、区間が 0 を外すのに要る対の数の見積もりに使う（目安: 対の差の標準偏差 ≈ √2·σ なので、平均の差 d を見分けるには対が 8σ²/d² 程度）。
- S3 の採否は既存の規則（決定的後処理の 2 腕比較、事前基準を先に固定、`docs/stall_escape.md` §13 の 4）。
- **追加の報告（PROPOSAL、§11 の R6）**: 対が少ない（8〜20）ときは、p 値の代わりに「新しい腕が良い確率」を出す（ベイズ的な性能比較。対ごとの勝ち・負け・引き分けの数から、勝つ確率の事後分布の中央値と 95% 区間）。採否の規則そのものは変えない（区間の判定は従来どおりブートストラップ）。
