# シーソー（重みや段を動かすと違反が族のあいだを移る現象）を改良拡張する設計書

- 状態: **設計のみ・未実装**（2026-11-01、ユーザー「シーソーを改良拡張する」）。コード・既定出力は不変。
- 「シーソー」の意味（仮定）: リポジトリにこの語は無い。外部提案（`docs/weightless_objective.md` §3.3）が W2 を「シーソー現象」と呼んだので、それを指すと仮定した。
  W2＝重みを動かすと、ある族が減る代わりに別の族が増え、必須は変わらない。測定の例（`docs/business-logic.md` §2）:
  - 3.727.14（high 25→50・c3mn 50→25、6 fixture×seed 3×60 秒の 18 組）: high −0.72、c3mn −0.11、c1 +1.56、c3m +1.83、fair −0.44、必須の差 0。
  - 2026-10-26（c1 50→90・c3mn 90→50、実データ 4 件×seed 3×60 秒）: c1 −16.6、low +3.8、high +4.6、c3mn +0.4、必須の差 0。
- 関係する設計: `docs/weightless_objective.md`（段・許容ライン・案の保持）、`docs/membrane_search.md`（頭打ち盤面の部分問題）。

## 1. 問い: そのシーソーは本物か

族 A を減らすと族 B が増える、という観測には 3 通りの説明がある。直し方がまったく違うので、先に見分ける。

| 種類 | 何が起きているか | 直し方 |
|---|---|---|
| **本物の交換** | A と B を同時に減らす盤面が存在しない（パレートの前線の上を動いている） | 交換は避けられない。どこで止めるか（支点）を利用者が決める＝許容ライン・受容度の帯（`weightless_objective.md` §4.2・§4.2b） |
| **探索の見かけ** | A と B を同時に減らす盤面が存在するのに、探索が届いていない。重みを変えると探索の道筋が変わり、別の局所最適に落ちただけ | 探索を直す。両端の盤面のあいだを探す（§3.3）か、部分問題を厳密に解く（`membrane_search.md`） |
| **揺れ** | 同じ重みでも seed や実行時間で族の件数が揺れ、差が揺れの中に収まる | 対を増やす。結論を出さない |

今の記録（W2）は平均の差だけで、この 3 つを分けていない。3.727.14 の c1 +1.56 は 18 組中 9 組で増えただけで、残りは同じか減っている（`business-logic.md` §2）。

## 2. 用語

- **件数ベクトル**: 盤面の族ごとの件数（`ViolationReport.breakdown`）を並べたもの。必須（T0）の族と SOFT の族を含む。
- **優越**: 盤面 X が Y に優越する＝X の件数ベクトルがどの族でも Y 以下で、少なくとも 1 つの族で小さい。重みを使わない比較。
- **シーソーの組**: 同じデータで、重み（または段）だけが違う 2 つの腕の最終盤面の組。
- **交換率** r(A→B): 腕を替えたとき、A が 1 件減るあたり B が何件増えたか（対ごとの差の比、§3.1）。
- **支点**: 交換をどこで止めるかの位置。重みの比で暗黙に決まっていたものを、件数のラインで明示する。

## 3. 設計

### 3.1 シーソーの測定（出力不変、S1）

- 既存の `tools/loop/WeightSwapProbe.kt`（盤面の族ごとの件数を書く）と `tools/loop/weight_swap_stats.py`（旧→新の差の平均・95% 区間・増/減/同）を拡張する。
- 拡張点:
  1. 対ごとの差のベクトル Δ（新−旧）を残し、族どうしの**交換の表**を作る: 族の組 (A, B) ごとに、A が減った対で B がどれだけ増えたか（中央値と区間）、A と B が両方減った対の数、両方増えた対の数。
  2. 腕を 2 つでなく複数にする: 重みを 1 族ずつ ×0.5・×2 にした腕（族の数×2）。どの族を押すと、どの族が出てくるかの表になる（**シーソーの地図**）。
  3. 揺れの見積もり: 同じ腕を seed だけ変えて回し、族ごとの揺れ（SD）を出す。差が揺れの 2 倍に届かない組は「揺れ」に分類する。

### 3.2 本物か見かけかの判定（S2）

1. **集めた盤面での判定（安い）**: 同じデータで、すべての腕・seed の最終盤面を 1 つの集合にする。ある腕の盤面が、別の腕の盤面に優越されていたら、その組のシーソーは少なくとも一部が**見かけ**（両方を減らせる盤面が実際に見つかっている）。
   - 出すもの: データごとに、優越されていない盤面（非劣の盤面）の数と、各腕の盤面のうち優越されたものの割合。
2. **厳密な判定（重い、PC のみ）**: ε 制約で前線の点を求める。「必須 ≤ 今の値、A ≤ a のもとで B を最小化」を、a を今の値から 1 件ずつ動かして解く。
   - 既存の `tools/loop/hard_floor_cpsat.py`（`HardFloorExport.kt` の書き出しを読み、最小 HARD を CP-SAT で解き、解を `UnifiedViolationChecker` で照合する）を、SOFT の族を制約・目的に足す形で拡張する。
   - 出すもの: 族の組ごとの本当の前線（A を a にしたときの B の最小）。観測した盤面が前線から何件離れているか＝**見かけの量**。
   - 前線から離れていなければ本物の交換。離れていれば、探索を直す余地がある。

### 3.3 シーソーを割る探索（見かけのとき、S3）

- 2 つの腕の盤面（片方は A が少なく、もう片方は B が少ない）を両端にして、そのあいだを探す。
- 既存の `EliteRelinking`（エリート解の Path Relinking＝2 つの盤面の中間を歩いて良い盤面を拾う）を使う。採否の比較だけを、**両端のどちらかに優越する盤面**を拾う形に足す（今は `betterReport` だけ）。
- 優越する盤面が見つかったら、それを今の比較器にかける（今の出力より良ければ採る）。比較器で負けても、§3.4 の案として保持できる。
- 中間に見つからなければ、`membrane_search.md` の細胞（A と B の違反が重なる職員×日）を厳密に解く。

### 3.4 支点を利用者が置く（本物のとき、S4）

- 本物の交換と分かった族の組は、重みの比ではなく件数で止める位置を決める:
  - 段が違う族どうし（例: c1 は T2、high は T1）: 上の段が勝つ（`weightless_objective.md` §4.3）。止める位置は上の段の許容ライン θ で決める。
  - 同じ段の族どうし: 段の中の比べ方（和か leximax、同 §4.2・§4.2c）で決まる。
  - どちらも、受容度の帯（同 §4.2b）を使えば「上限超過は 1 件までなら、期間の制約を優先」のような支点を件数で書ける。
- 画面: 前線の 2〜3 点を並べ、交換率を件数で示す（例:「上限超過を 1 件減らすと、期間の制約が約 2 件、推奨の並びが約 2 件増えます」）。並べ方は `weightless_objective.md` §6.1 の案の保持（本命・段の極端案・妥協案）。

### 3.5 シーソーの地図で段を決める（S5）

- §3.1 の地図で、互いに強く押し合う族の組（片方を減らすと、もう片方がほぼ必ず増える）を見つける。
- 強く押し合う族を**別の段**に置くと、上の段が常に勝ち、下の段の族は放置される（実機ログの fair・apt が c1 に負け続けるのと同じ形、`weightless_objective.md` §3.4.2）。
- 同じ段に置けば、段の中の比べ方とラインで支点を決められる。
- そこで、`weightless_objective.md` の Q1（段の割り当て）を決めるときの材料として、地図の「強く押し合う組」を示す。決めるのは利用者。

### 3.6 シーソーの連鎖（S6）

- 3.727.14 の例では high を押すと c1 と c3m の 2 つが出てきた。1 つの族を押すと複数の族へ分かれて出る、または A→B→C と連鎖することがある。
- §3.1 の表を、族を節・交換率を辺にした有向グラフにする。連鎖の経路（例: high → c1 → c3m）が見えれば、どの族のラインを動かすとどこまで波及するかを事前に示せる。

## 4. 段階と採否

| 段階 | 内容 | 出力 | 事前基準 |

## 5. 注意

- `docs/business-logic.md` §2 が 3.727.14 の測定の記録として挙げる `tools/loop/results/w14-2026-10-31-high50-c3mn25.txt` は、2026-11-01 の main（7f40fac）に無い。数値は business-logic.md の本文にしか残っていない。S1 で測り直して結果をコミットする。
- 交換率は平均の比なので、対ごとの揺れが大きいと意味を持たない。表には必ず区間と、増/減/同の数を添える。
- 前線は必須（T0）を今の値に固定して求める。必須を緩めた前線は出さない（必須はどの設計でも緩めない）。
