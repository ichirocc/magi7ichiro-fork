# シーソー（族のあいだの違反の移動）仕様

対象: `ichirocc/magi7ichiro-fork`（Android アプリ「MAGI」、看護師の勤務表の最適化）。最終更新 2026-11-24（3.727.129・K 人の組の厳密スイープの測定）。
読み手: 会話履歴を持たない AI と人。この文書とリポジトリだけで、判断・測定・実装ができることを目的にする。

## 0. 読み方

### 0.1 前提知識

- 勤務表は「職員 × 日」の表で、各マスにシフト（休・日勤・夜勤など）が 1 つ入る。
- 違反は **族**（種類）ごとに数える。21 族（`MirrorKeys.all`）。うち **必須** 6 族（`MirrorKeys.hard`: groupViol・covU・c3n・c3w・pref・extWish）、残り 15 族は **できれば守る**（SOFT）。
- 採否は 1 か所の比較だけで決まる: `betterReport`（`MirrorCore.kt`）＝ 必須の件数 → 重み付きの点数 → 合計件数 の辞書式。点数を出すのは `UnifiedViolationChecker`（source of truth）。
- 重み（`ObjectiveWeights`）は利用者が選ぶ「直す順番」で切り替わる。既定の優先順位では、必須の族は 8000〜11000、できれば守る族は 200（下限割れ・期間の制約・上限超過・回避の並び）・50（人員過剰・グループ内の回数のばらつき）・20（守るとよい並び・推奨の並び・グループのレンジ・グループペア・スキルグループのレンジ・スキルグループペア・個人の合計・目安の回数との差・シフトの間隔）・1（曜日の偏り）。重み（従来）では値が違う。画面の重み表（`MagiDashboardCards` の重み表カード）は選んだ方式の値を出す（表示だけ）。

## 1. 定義

**シーソー**: 重み（または優先の段）を変えたとき、ある族の件数が減る代わりに別の族の件数が増え、必須の件数は変わらない現象。

| 用語 | 定義 |
|---|---|
| 件数ベクトル f(x) | 盤面 x の族ごとの件数（`ViolationReport.breakdown`）。f_A(x) は族 A の件数 |
| 優越 x ≺ y | すべての族で f(x) ≤ f(y)、かつどれかの族で f(x) < f(y)。重みを使わない比較 |
| 見かけ（優越） | 観測した盤面 x に優越する盤面が存在する（必須が x 以下）＝探索が届いていない。**判定はこちらで行う** |
| 見かけ（重み） | 今の重みで x より点数の低い盤面が存在する。別の族を増やしていてもよい＝見かけ（優越）より弱い |
| 本物の交換 | 必須が同じ盤面の中で、x に優越する盤面が存在しない（前線の上）。どちらを取るかは利用者の判断 |
| 揺れ | 差が乱数のばらつきの範囲（95% 区間が 0 を含む） |
| 対 | 同じデータ・同じ乱数で 2 つの設定（腕）を走らせた最終盤面の組。**同じ乱数でも盤面は再現しない**（並列・壁時計の予算）ので、同じ探索の 2 回ではない |
| fixture | `app/src/test/resources/` の 6 盤面: golden・sample_v6・sept2026・oct2026_grid・blocked_covu・full_coverage |
| 競合・調和・独立 | 族 A を押した（A の重みを上げた）とき、ΔB の平均の 95% 区間が正＝競合、負＝調和、0 を含む＝独立 |
| 1 組の手（複合近傍） | 単独では採点で落ちる手（1 手目）と、それで崩れた族を直す手（2 手目）を 1 つの手として採点する探索の手 |
| K 最適 | どの K 人の行を変えても、必須と重みで良くならない盤面（重みが同じで合計件数だけ少ない盤面は見ない）。前線の上（本物の交換）とは別＝K 人より多くを同時に変える盤面は見ていない |
| 膝点 | 前線の断面で、隣どうしの交換率（Δf_B／Δa）が最も大きく変わる点（Deb & Gupta 2011 の考えを整数の断面に写したもの）。ほかの定義（ユートピア点からの距離・角度・最遠点）は使わない。点が 3 つ未満なら両端だけ（`seesaw_detail.md` §6.4・§11 の R4） |

## 2. 守ること（不変条件）

### 2.1 してはいけないこと

| # | 規則 | 理由 |
|---|---|---|
| I1 | 優越・前線は、必須の件数が同じ盤面どうしでだけ比べる | 必須は常に最上段で緩めない |
| I2 | 盤面の採用は `betterReport` だけで決める。優越などは「拾う」条件で、採る条件ではない | 採否の比較は単一ソース |
| I3 | ε 制約で得た盤面は、目的の族が同じ値なら残りの族で辞書式に整える | 弱効率解を案に出さない |
| I4 | 測定（S1・S2・K 人の組の厳密スイープ）は出力不変（`tools/` だけ） | 測定と改修を分ける |
| I5 | **製品の重み・閾値・必須の族・優先の段を変えない**。変えるのは業務担当者の明示の数値指示があるときだけ（HF77、`CLAUDE.md`） | 業務ルール |
| I6 | 差には必ず 95% 区間と増/減/同の数を添える | 平均だけでは揺れと区別できない |
| I7 | 見かけ（重み）だけを根拠に「本物の交換ではない」と言わない | 重みで良い盤面は別の族を増やした交換かもしれない |
| I8 | 希望（`wishes`）で固定したマスは動かさない（`Problem.wishLocked`）。希望違反（pref）は業務ルール上の必須 | `docs/business-logic.md` |
| I9 | 重みを周期的に揺らす・受理で必須を一時的に割り引く手（戦略的振動）を入れない | 2.52.0→2.55.0 で測って否決（§7） |

### 2.2 採否の規則（新しい手・設定を既定にするとき）

- 同じ盤面か同じ (データ, 乱数) の **対** で旧と新を比べる。別々の時刻に走らせた結果どうしを突き合わせない（負荷で変わる）。
- 合格: **必須の増加 0**、**勝ち > 負け**（`betterReport` の順）、後処理の時間の増加が予算に収まる。
- 区間は 95% ブートストラップ（4000 回、乱数 7）。対が 8 未満なら判定しない。
- 道具: 対の比較は `tools/loop/` の各 Probe（例: 同じ盤面に旧版と新版の研磨をかける）。生データの置き場は `tools/loop/results/`（`.gitignore` なので `git add -f`）。

## 4. 判定の手順（族の組 A, B について）

```
入力: 腕 P（A を押す）と腕 Q（今のまま）の対の集合、各対の最終盤面
1. 揺れ: ΔA・ΔB の 95% 区間が 0 を含むなら「揺れ」。対を増やす（8 未満なら判定しない）
2. 見かけ（優越）:
   2a. 集めた盤面どうしの優越（安いが、21 族ではほぼ何も見つからない）
   2b. 盤面ごとのパレート判定（主判定）: 腕 P の各盤面 x について CP-SAT で
       最小化 Σ_f f(y)  条件: 必須(y) ≤ 必須(x)、すべての族で f(y) ≤ f(x)
       最適値 < Σ_f f(x) なら「見かけあり」。最適の証明つきで差 0 なら x は前線の上
   2c. （補助）K 人の組の厳密スイープ（TOOL）: すべての K 人の組について、ほかの職員の行を固定して CP-SAT で解く。
       良い盤面が出れば探索が届いていない証拠（見かけ（重み）、I7 のとおりこれだけで本物でないとは言わない）。
       下限が入力以上なら K 最適。K 最適は前線の上の証明ではない（判定は 2b）
3. 2 で見かけが無く、最適の証明がある → 「本物の交換」。時間切れ（FEASIBLE）なら「未決」
```

- 原因で直し方が変わる: **見かけ → 探索を直す（§6 の 1 組の手など）**、**本物 → 利用者が止める位置を選ぶ（S4）**、**揺れ → 測定を増やす**。
- A と B の 2 族だけで両方減った盤面は、見かけの証拠にしない（第 3 の族へ移っただけのことがある）。

## 7. 否決した案（REJECTED・再提案しない）

| 案 | 否決の根拠 |
|---|---|
| 戦略的振動（受理で必須を一時的に割り引く、重みを周期的に揺らす。「A 軸・B 軸を傾ける」案を含む） | 2.52.0 で入れ、実データの等価ベンチで一貫して悪化（AUC +5〜+15%）＝2.55.0 で戻した。現実のデータは壁の向こうに良い盤面が無い。2026-11-24 の 2 軸案も F8（必須 3 は最少と証明）・I8（希望は必須）・この否決で見送り |
| 競合を相関係数・競合率で判定する | 対は同じ探索の 2 回ではないので、対ごとの向きは重みの効果を表さない。有意な動きを取り逃した（`seesaw_detail.md` §13.2） |
| 揺れを「平均の差 < 2σ」で判定する | 押した族自身まで揺れと判定した。区間で判定する |
| nonlinear restart・GLS スイープ・targeted-perturb・big-destroy・softFocusProb | `CLAUDE.md` の否決済みの一覧（作業記録に数値） |
| 職員 1 人の全合法行を列挙して直積を総当たりする（Prefix Trie・分枝限定で枝を刈る案を含む） | 希望・置けるシフト・長さ 2 の禁止の並びを入れても、1 人の合法行は中央値で約 10^15〜10^16 本（oct2026・golden・sept2026、DP で数えた上界、2026-11-24）＝列挙できない。K 人の組は CP-SAT で解く（§4 の 2c） |

## 9. 実装者のチェックリスト

1. 変えようとしている手が §7 に無いか確かめる。
2. 重み・段・必須の族・希望の固定に触れない（I5・I8）。
3. 新しい手は、既存の採点（`betterReport`）でだけ採る（I2）。
4. 先に「その手で採れる盤面が実際にあるか」を、最適化後の盤面（付属の 6 件・端末の盤面）で数える（測定だけ、製品コードを変えない。§4 の 2c の組スイープが使える）。
5. 作ったら §2.2 の対の比較で採否を決め、数値を `docs/history/` と §6 の表に書く。組スイープで良い盤面が 0 件でも言えるのは K 最適まで。本物の交換かは 2b で判定してから Q-S4 へ進む。
6. 研磨の診断行（例: `GapPolish` の「残った理由」）に、却下の主因（族）を出す。次の手の材料になる（F7）。
