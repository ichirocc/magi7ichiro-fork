## 0. 結論
1. **HARD の壁になる設定は「個人の上限 0」だけ**（`Problem.mayPlace` の除外＝3.507.0「最適化器だけ除外」）。「ちょうど」（下限＝上限、例 休 10回）と
   0 でない上限・下限は low/high（要調整）で、keep-best も VCR も必須を先に比べる＝必須を減らす手を拒まない。実データで「ちょうど」16 件の
   片側緩和（上限+1／下限−1）はどれも必須 ±0。グループの担当可（45 通り）も ±0（§13）。→ **S6 v1 の候補は上限 0 だけ**（§14 Q1）。
2. **1 件ずつでは足りない**: 実データの アリフ 10/8→10/9 の禁止の並び（Dﾃ→A4）は、上限 0 を 1 件だけ緩める 19 通りのどれでも ±0。
   解けるのは **組**（荒井 Cｵ ＋ アリフ Pｼ、同時に）。S5 の「1 件ずつ・合計しない」をそのまま移せない＝**候補の単位は「組」**。
3. **候補の見つけ方（原理）**: ① 上限 0 を全部外した state で解けるか探す（解けなければ「上限 0 は壁でない」）→ ② 解けた盤面が
   使った上限 0 だけを残す → ③ 1 件ずつ外して同じだけ減るなら落とす（削除フィルタ、順序固定＝決定的）→ ④ 残った組を実際に緩めた
   state で同じ探索を回し、設定そのままの対照との差を出す。探索は「本実行の入口と同じ clear → VCR（既定 Params）」と
   「起点の窓の日ごとの同日 2 人交換（必須を増やさないもの）を 1 つ当ててから VCR」の良い方。
4. **手で置いた上限 0 の勤務は別枠**（前提）: 実データは 桒澤 10/10 Aｱ・10/11 Cｵ、大島 10/9・10/29 Cｱ が上限 0 のまま手で置いてある。
   本実行の入口の clear がこれを外すので、**設定そのままで「もう一度つくる」と必須 5→8〜9 に悪化し keep-best で捨てられる**（30 秒×2 で 9・9）。
   この 3 件（桒澤 Aｱ・桒澤 Cｵ・大島 Cｱ）は「手で置いた勤務に合わせる」前提として、壁とは分けて出す。
5. **確定は「設定を緩めて、試算の手順を当てる」**（§14 Q3 決定）: 実データでは、組を緩めた state でも **30 秒の本実行×3 はこの 9 セルの連鎖に
   届かない**（必須 5 のまま）。「緩めて本実行」だけでは試算の数字が出ない。1手の適用（FixSuggester）と同じく、利用者が押したときだけ
   手順のセルを当てる（盤面は試算の結果そのもの＝`check(緩めた state, B＋手順)` が試算の Rr と一致）。
6. **設定値は自動で変えない**（HF77）。候補を押すまで state は変わらない。上げ幅は `mayPlace` を外す最小の 1（0→1）。
   上げた後の回数が 1 を超える（手置き・手順で 2 回以上になる）ときは high（要調整 25）が付くことを文言で言う。

## 1. 目的と非目的
- 目的: 必須違反が「利用者自身の設定」で塞がれている盤面で、**どの設定をどれだけ緩めれば、どの手順で必須が減るか**を、緩める前に見せる。
- 非目的（S5 から引き継ぐ決定・再提案しない）:
  - 自動で選ばない・自動で確定しない・設定値を自動で変えない（HF77、3.492.0・3.401.0）。
  - SOFT（要調整）の見込みは出さない（件数は必須だけ）。
  - 重みを変えない。探索動学・採用基準を変えない（試算は既存の VCR と checker を読むだけ）。
  - 「ちょうど」・0 でない上限・下限・グループの担当可・必要人数は v1 の候補にしない（§0-1、§14 Q1・Q2）。

## 3. 何を数えるか
記号: st＝いまの state、B＝盤面、pre＝手置き前提（B が使っている上限 0、希望で固定したセルを除く）、R＝壁の組、
search(s, B)＝§4 の探索の必須件数。

| 記号 | 定義 | 意味 |
|---|---|---|
| H0 | check(st, B).hard | いま |
| Rk | search(st, B) | 設定そのままでもう一度つくった見込み |
| RkH | search(st+pre, B) | 手置きに合わせるだけ |
| Rr | search(st+pre+R, B) | 手置きに合わせ、壁も緩める |
| P_keep / P_pre / P_relax | min(H0, Rk) / min(H0, RkH) / min(H0, Rr) | keep-best を入れた予測 |
| att | P_keep − P_relax | 何も変えずにもう一度つくる場合より減る分 |
| attWalls | P_pre − P_relax | そのうち壁 R に帰属する分（手置きに合わせる分を除く） |

- S5 の a（同じ盤面で確実に消える分）に当たるものは無い（上限は checker の必須を直接は変えない）。**すべて見込み**。
- ただし §6 の推奨確定（手順を当てる）では、確定後の必須は `check(st+pre+R, B＋手順)`＝Rr と**一致**（決定的）。「確実に」を使えるのはこの形だけ。

## 4. 試算エンジン
- **探索**（`RelaxTrial.search`、決定的・止められる）: clear → VCR（既定 Params・候補プール空）と、窓の各日・各 2 人の同日交換で
  必須を増やさないもの 1 つ → VCR、の中の最良（`betterReport`）。
  - 同日交換の種を足した理由: 実データの解は 10/9 の「佐藤 Cｵ↔荒井 休」（必須 ±0）を先に置かないと VCR が届かない。
    VCR 単独は Params を maxK 8・beam 32・評価 512 まで広げても、上限 0 を全部外しても 5 のまま（§13）。
- **候補の組**（`RelaxTrial.discover`）: §0-3 の ①〜④。①で起点のセルが必須のまま残るなら NoWall。組が `maxRelaxes`（既定 3）を超えたら NoWall。
- 所要（ホスト）: アリフ の起点 1 件で 16〜26 秒（search を 対照・前提・全外し・削除フィルタ 2 回・最終 の 6 回）。端末は数倍。§14 Q7。
- VCR の語彙の限界: 削除フィルタは探索が見つけた範囲で最小。実データでは アリフ 10/8 を Pｼ にする手（アリフ Pｼ の上限 0 を要する）が残ったが、
  総当たりでは アリフ 10/8 を 休 にする手（アリフ Pｼ 不要、要調整もわずかに良い 39238 対 39338）がある。→ 組は「探索が見つけた十分条件」で、
  最小とは言わない（文言で「この組で」）。

## 6. 確定操作
決定（§14 Q3）＝「**この組で緩めて、手順を当てる**」を Undo 1 段で:
1. 照合: `stateKey(st) == token.stateKey && boardKey(B) == token.boardKey`（データの指紋＝盤面・希望・制約・データに保存される設定。実行設定は含まない）。
   違えば「勤務表か設定が変わりました。もう一度試算してください。」で何も変えない。
1b. 再現の確認: `check(apply(st, pre+R), B＋手順).hard == Rr` でなければ（手順の from が盤面と違う場合も）「試算の手順を当てても同じ結果に
   なりませんでした。勤務表と設定はそのままです。」で何も変えない（黙って上書きしない）。
2. `runBlockedByInFlight` なら終わり。試算ジョブを取り消す。
3. `ns = RelaxTrial.apply(st, pre + R)`、`nb = B＋手順`（手順は Move の列、盤面は試算時の B に対して当てる）。`ensureValidForRun(ns, nb)` が偽なら終わり。
4. `pushUndo("設定を緩めて、手順を当てる")`（(st, B) を 1 回だけ積む）。`state = ns`、盤面 `nb`、`structureEdited = true`、refreshCheck。
5. `saveNow()`。操作ログ「S6: 組・H0/Rk/RkH/Rr → check(ns, nb)」。
6. 本実行はしない（利用者が続けて「もう一度つくる」を押せる。keep-best の基準が (ns, nb) になるので、その後も必須は Rr 以下）。
- 代案（採らない）: 「緩めて本実行」（S5 と同形）。実データでは 30 秒×3 で試算の手順に届かず必須 5（§13）。S5 の「仮盤禁止」は試算の盤面を
  **黙って**採らない決定と読み、1手の適用と同じく**手順を言葉で見せてから押したときだけ当てる**形はその外（§14 Q3 で利用者が確認）。
